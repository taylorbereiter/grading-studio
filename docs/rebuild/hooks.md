# Hooks: what the new app must do that no button shows (pass 3)

Written 19 Nov 2026 by the audit thread, against main (eb478a1). The switch branch has the same rows except where noted.

Each row has an ID (H-001…) and the slice that owns the fix. Slices take their rows into their ledgers by ID, and the audit thread re-checks them the same way as gaps.md rows (see status.md).

Three readers went through the code:
1. Every write that saves a whole shared record, traced back to where its value is loaded (60 write paths).
2. Every hook, setter and stub the lifted engines expect the screens to supply, plus every no-op that replaced real work (137).
3. Everything the current app does without a press: on open, on save, on a timer, on focus, on unload, and on a change from another window (103).

Only rows that need work are listed here. The "supplied" and "safe" rows are in hooks-raw/.

## Getting saved comments back (gs.bank) after the preview bug

**Is gs.bank in the copies?** Yes, in all of them:
- The browser's safety copies (database grading-studio-safety). Each holds every gs.* key (src/migrate.js:22). Only 3 are kept, and they are made before a change to how work is saved, or before putting back or going back. They are not made daily.
- The folder's dated snapshots (snapshots/*.gsnap). Each holds every gs.* key except per-download keys (src/folder.js:311). One is made each day she works, and one before anything risky.
- The Drive sync file and the take-home file. Both carry the gs.* keys.

**Can the bank alone be put back?** Not from Go back in time. Putting back a safety copy or a snapshot replaces everything, including marking done since then.

**But there is a gentler way that already works.** Wherever two copies of her work are joined, saved comments are joined as a union: every comment in either copy is kept, and nothing is removed (src/merge.js:901, `mergeLs`). That happens:
- on every Google Drive sync (src/app/drive.js:270);
- when work is brought in from the linked folder (src/folder.js:537, the take-in, not "go back");
- when a take-home file is brought in (src/takehome.js:375).

So a teacher whose list was cut down to one comment gets the rest back without losing anything else:
- **Signed in with Google:** press Sync now on a device that still has the full list, then Sync now on the computer where it was cut. The new app's Drive, folder and take-home code uses the same union (next/src/whole/drive.js:110, folder-run.js:467, takehome.js:280).
- **With a folder linked:** the folder's own copy is updated on each save, so it may already hold the cut list. A take-home file made earlier, brought in from Settings > Saving, brings the old comments back by union.
- **With neither:** the only copy is a safety copy, and that one can only be put back whole.

Caveats:
- Comments she deleted on purpose since that copy come back too.
- I could not check whether a sync pushed the cut list before pulling. Even if it did, the other device still holds the full list, and its next sync joins them.

Nobody needs to look at the teacher's comments for any of this.
